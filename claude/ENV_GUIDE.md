# ChatDesk Shared Environment Variable Guide
Three projects, three .env files. Each one has its own .env.example checked into git — copy it to .env locally and fill in real values. Never commit .env itself.

Variable,Where to get it
SECRET_KEY,"Generate once for Django, share securely via a password manager — never reuse across environments."
DB_*,From whoever set up the local/shared PostgreSQL instance (Jefferson or Veejay).
OPENAI_API_KEY,OpenAI Platform Dashboard → API Keys. (Generated by Jefferson). CRITICAL: This must only exist in the backend/.env file.
JWT_* lifetimes,"Already filled in .env.example with sane defaults (e.g., 15 mins access, 1 day refresh) — only change if the backend team agrees."
VITE_API_BASE_URL,http://localhost:8000/api/v1 for local web dev against your own backend instance.
EXPO_PUBLIC_API_BASE_URL,"Your local IP address (e.g., [http://192.168.1.](http://192.168.1.)X:8000/api/v1) so the React Native app on your physical phone/emulator can reach the Django server."

## Rules
Gitignore: .env is gitignored in all three projects. Do not bypass this.

Frontend Variables are PUBLIC: By build-time convention, frontend variables are embedded into the app. ReactJS requires the VITE_ prefix, and React Native requires the EXPO_PUBLIC_ prefix. Anything in those files ends up in the shipped bundle that users can inspect.

Backend Secrets: Secrets that must stay server-side (OpenAI API Key, JWT signing key, PostgreSQL password) only ever go in backend/.env. Never put the OpenAI API Key in web/.env or mobile/.env.

Keeping Examples Updated: When you add a new variable to the system, add it to the relevant .env.example with a placeholder value in the same commit. Don't let .env.example drift from what the code actually requires to run.
